## 1. เป้าหมาย: การจำลองต้องพิสูจน์อะไรบ้าง

| เกณฑ์คะแนน | หลักฐานที่ได้จากการจำลอง |
|---|---|
| Technical Feasibility (20%) | 2 โหนดทำงานจริงพร้อมกันและคุยกันผ่าน Wi-Fi · ทุก test case ใน C5 มีผล ผ่าน/ไม่ผ่าน พร้อมตัวเลขที่วัดได้ |
| Real-time (Instruction เน้น) | เวลาทำงานจริงของแต่ละ task (WCET) ที่วัดได้ ส่งให้ B แทนค่าประมาณใน B3 · เวลาตอบสนองจริงเทียบกับ NFR-01..04 |
| Power management | log การลดงานเมื่อ `away_timeout` (ปิดไฟ, รอบส่ง 5 → 15 s) · คำนวณพลังงานจาก A2 ข้อ 2.4 |
| Resource optimization | stack ที่ใช้จริงของแต่ละ task (`uxTaskGetStackHighWaterMark`), heap ว่าง, utilization ที่วัดได้ |
| Documentation Quality (15%) | ภาพหน้าจอ, ภาพคลื่น PWM จาก logic analyzer, log ที่มีเวลากำกับ, ลิงก์โปรเจค Wokwi ที่กรรมการเปิดดูเองได้ |

## 2. เตรียมเครื่องมือ

1. สมัคร Wokwi (https://wokwi.com) ฟรี สร้าง 2 โปรเจคชนิด **ESP32 (Arduino)** ชื่อ `swer-desk-node` และ `swer-room-node`
2. เพิ่มไฟล์ `libraries.txt` ในแต่ละโปรเจค
   - โต๊ะ: `PubSubClient`, `ArduinoJson`, `Adafruit SSD1306`, `Adafruit GFX Library`
   - ห้อง: `PubSubClient`, `ArduinoJson`, `DHT sensor library`, `Adafruit Unified Sensor`
3. เก็บต้นฉบับใน repo ทุกครั้งที่แก้ (กรรมการตรวจย้อนได้):

```text
08_code/
├── SIMULATION_GUIDE.md      ← ไฟล์นี้
├── common/config.h          ← ค่าเกณฑ์จาก D1, ชื่อหัวข้อ MQTT, TIME_SCALE
├── desk_node/
│   ├── sketch.ino           ← สร้าง task, i2c_lock, ข้อมูลกลาง (A)
│   ├── presence.cpp/.h      ← logic B2
│   ├── light.cpp/.h         ← logic D3
│   ├── comm.cpp/.h          ← A3 + NTP
│   ├── diagram.json         ← วงจร Wokwi
│   └── libraries.txt
└── room_node/
    ├── sketch.ino
    ├── air.cpp/.h           ← logic C2
    ├── comm.cpp/.h
    ├── diagram.json
    └── libraries.txt
```

แยกไฟล์ตามโมดูลตามที่ role A กำหนด ("แยกไฟล์ตามโมดูล") ทำให้เจ้าของโมดูลตรวจโค้ดของตัวเองได้ง่าย

| ชิ้นส่วน Wokwi | แทนอะไร | ต่อ |
|---|---|---|

| `wokwi-potentiometer` | CO₂ ของ SCD41 | SIG → **35** (ADC1) · โค้ดแปลง `co2 = map(analogRead(35), 0, 4095, 400, 5000)` ตามช่วงวัดใน NFR-12 |

## 4. ตั้งค่าสำคัญในโค้ด

| เรื่อง | ค่า | หมายเหตุ |
|---|---|---|
| Wi-Fi | `WiFi.begin("Wokwi-GUEST", "", 6);` | เครือข่ายจำลองของ Wokwi ไม่มีรหัส ระบุ channel 6 ให้ต่อเร็วขึ้น |
| MQTT broker | `broker.hivemq.com` port 1883 | prefix หัวข้อเฉพาะทีม เช่น `swer-<รหัสสุ่ม>/r1/` (A3 ข้อ 3) |
| NTP | `configTzTime("ICT-7", "time.navy.mi.th", "clock.nectec.or.th", "pool.ntp.org")` | A3 ข้อ 7 |
| task | `xTaskCreatePinnedToCore(..., 1)` ทุก task ของ B, C, D, A | core 0 เป็นของ Wi-Fi (A-T หมายเหตุ 2) · priority ตาม B3 (RMS) |
| `i2c_lock` | `xSemaphoreCreateMutex()`, รอ `pdMS_TO_TICKS(50)` | A1 ข้อ 7 |
| PWM | `ledcAttach` / `ledcSetup`: LED 5 kHz 13 บิต, buzzer 4 kHz, พัดลม 50 Hz | A2 ข้อ 3–4 |
| ค่าเกณฑ์ | อยู่ใน `common/config.h` ที่เดียว ตรงกับ D1 ข้อ 6 ทุกตัว | ตรวจเช็คลิสต์ A4 "ค่าเกณฑ์ตรงกับ D1" ได้ในไฟล์เดียว |

### 4.1 การเร่งเวลา (สำคัญมาก)

test case หลายข้อต้องรอ 20 นาที, 30 นาที, 5 นาที ให้ใส่ตัวคูณเวลาไว้ที่เดียว:

```cpp
// common/config.h
#define TIME_SCALE 60   // 1 = เวลาจริง, 60 = 1 นาทีในระบบใช้ 1 วินาทีจริง
#define MIN_TO_MS(m) ((uint32_t)((m) * 60000UL / TIME_SCALE))
```

- ใช้ `MIN_TO_MS(20)` แทนเลข 1,200,000 ทุกที่ → เตือนพักสายตาเกิดที่ 20 วินาที
- **รอบของ task (100 ms, 200 ms, 5 s) ห้ามเร่ง** เพราะเป็นตัวเลขที่ใช้วิเคราะห์ real-time
- เขียนในผลทดสอบทุกครั้งว่ารันที่ `TIME_SCALE` เท่าไร และรันซ้ำที่ `TIME_SCALE 1` อย่างน้อย 1 ครั้งสำหรับ TC-B-02 (เตือน 20 นาทีจริง) เพื่อยืนยันว่าตัวคูณไม่ได้ซ่อนปัญหา

### 4.2 คำสั่งทดสอบผ่าน Serial Monitor

ใส่ตัวรับคำสั่งใน task ความสำคัญต่ำสุด เพื่อจำลองเหตุผิดพลาดที่ทำด้วยมือไม่ได้ใน Wokwi:

| คำสั่ง | ทำอะไร | ใช้กับ |
|---|---|---|
| `wifi off` / `wifi on` | ตัด/ต่อ Wi-Fi | TC-A-03 |
| `fault bh1750` | ให้การอ่านแสงคืนค่าผิดพลาด | TC-D-06 |
| `fault scd41` | ให้การอ่าน CO₂ คืนค่าผิดพลาด | TC-C-05 |
| `fault ld2410` | หยุดข้อมูลเซนเซอร์คน | B2 SENSOR_FAULT |
| `time 18:30` | ตั้ง `time_of_day` ทดสอบสีแสง | TC-D-02 |
| `away` | บังคับ `away_timeout = true` | TC-D-03, TC-A-08 |
| `stats` | พิมพ์ WCET สูงสุด, stack ที่เหลือ, heap ว่าง, ข้อความหาย | A5, B3 |

## 5. ลำดับการทำ (ทำทีละขั้น ผ่านแล้วค่อยไปขั้นต่อไป)

| ขั้น | ทำอะไร | ผ่านเมื่อ |
|---|---|---|
| 1 | ต่อวงจรเปล่าทั้ง 2 โหนดตามข้อ 3 + โค้ดที่สร้าง task ว่างๆ | กด Start แล้ว Serial พิมพ์ชื่อ task ทุกตัว ไม่มี reset |
| 2 | โหนดห้องเดี่ยว: logic C2 + ไฟสถานะ + พัดลม | TC-C-01..06 ผ่าน (ใช้ `room_occupied_count` ปลอมในโค้ด) |
| 3 | โหนดโต๊ะเดี่ยว: logic B2 + D3 + OLED | TC-B, TC-D ผ่าน (ใช้ `air_status` ปลอม) |
| 4 | ต่อ MQTT ทั้ง 2 โหนด | TC-A-01, TC-A-02 ผ่าน |
| 5 | กรณีผิดพลาด | TC-A-03, TC-A-04, TC-C-05, TC-D-06 ผ่าน |
| 6 | ขยายระบบ | TC-A-06 (เปิดโหนดโต๊ะตัวที่ 2 ด้วย `desk_id = 2`) ผ่าน |
| 7 | วัดเวลาและทรัพยากร (ข้อ 6) | ได้ตาราง WCET ส่งให้ B |
| 8 | รัน SCENARIO-01, 02 ของ C5 ตั้งแต่ต้นจนจบ | อัดวิดีโอหน้าจอไว้ใช้ตอน demo |

> **รัน 2 โหนดพร้อมกัน:** เปิด 2 หน้าต่างเบราว์เซอร์วางข้างกัน (ไม่ใช่ 2 แท็บ) เพราะเบราว์เซอร์มักลดความเร็วแท็บที่ไม่ได้แสดงอยู่ ทำให้การจำลองช้าลงและเวลาเพี้ยน
> ดู **Simulation speed** มุมบนของ Wokwi ถ้าต่ำกว่า 100% มาก ให้ปิดโปรแกรมอื่น เวลาใน log ที่ใช้ `millis()` เป็นเวลาในการจำลองจึงยังถูกต้อง แต่การจับเวลาด้วยนาฬิกาจริงจะคลาด

## 6. วัดค่าที่ใช้ตอบเรื่อง real-time และทรัพยากร

```cpp
// ครอบงานในแต่ละรอบของ task
int64_t t0 = esp_timer_get_time();
/* ... งานของรอบนี้ ... */
int64_t dt = esp_timer_get_time() - t0;      // µs
if (dt > wcet_us[TASK_ID]) wcet_us[TASK_ID] = dt;
```

| ค่าที่เก็บ | วิธี | ไปลงที่ |
|---|---|---|
| WCET ของแต่ละ task | ค่าสูงสุดอย่างน้อย 100 รอบ (`stats`) | B3 (แทนค่าประมาณ), เล่มหัวข้อ 6 |
| utilization จริง | Σ(WCET / period) จากค่าที่วัด | B3 |
| เวลาตอบสนอง | log มีเวลากำกับ เช่น `[12.345] occupied=1` แล้วลบเวลาเหตุกับเวลาผลลัพธ์ | NFR-01..04 ใน A5 |
| stack ที่ใช้ | `uxTaskGetStackHighWaterMark(handle)` แล้วตั้งขนาด stack ให้เหลือเผื่อ ~25% | เล่มหัวข้อ 6 (การใช้ทรัพยากร) |
| heap ว่าง | `ESP.getFreeHeap()`, `ESP.getMinFreeHeap()` | เล่มหัวข้อ 6 |
| ความถี่ PWM | logic analyzer → กด Stop → ได้ไฟล์ `.vcd` → เปิดใน PulseView แล้ว capture ภาพ | NFR-09 (5 kHz), พัดลม 50 Hz |
| ข้อความหาย | นับจาก `seq` ที่กระโดด | A5, ความน่าเชื่อถือของ A3 |

## 7. เก็บหลักฐานสำหรับ A5

ทุก test case ต้องมี:

| ช่อง | ตัวอย่าง |
|---|---|
| รหัส + requirement | TC-A-01 / FR-14, FR-19, NFR-01 |
| `TIME_SCALE` ที่ใช้ | 1 |
| ค่าที่ป้อน | หมุน pot ให้ CO₂ 1,050 ppm ที่เวลา 12.30 s |
| ผลที่คาดหวัง | จอโต๊ะแสดง ≥ 1,000 ppm ภายใน 10 s |
| ผลที่ได้จริง | แสดงที่ 18.7 s → ใช้เวลา 6.4 s |
| ผ่าน/ไม่ผ่าน | ✅ |

| ถ้าไม่ผ่าน | สาเหตุ → วิธีหาสาเหตุ (debugging technique) → แจ้งเจ้าของโมดูล → ผลรอบแก้ |
