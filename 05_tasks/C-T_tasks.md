## ตารางข้อมูลงานย่อย (แบบฟอร์ม T)

งานย่อยทั้งหมดในตารางนี้ทำงานอยู่บน **โหนดห้อง (Room Node ESP32)** ภายใต้ระบบปฏิบัติการ FreeRTOS:

| ชื่องานย่อย | ทำอะไร | ทำทุกกี่ ms (Period $T_i$) | ต้องเสร็จภายในกี่ ms (Deadline $D_i$) | ใช้เวลาทำประมาณกี่ ms (Execution Time $C_i$) | ใช้ของร่วมกับงานอื่นไหม (Shared Resources) |
|---|---|---|---|---|---|
| **1. `Task_Read_Air`** (อ่านค่าอากาศ) | อ่านค่า $\text{CO}_2$, อุณหภูมิ และความชื้นจากเซนเซอร์ SCD41 ผ่านบัส I²C (รวมตรวจเช็ค CRC และความถูกต้องของค่า) แล้วบันทึกลงตัวแปรกลาง `air_status` | **5,000 ms** (5 วินาที) | **500 ms** | **~5 ms** (เวลาอ่านข้อมูล I²C 9 ไบต์ที่ความเร็ว 100 kHz ใช้เวลาประมาณ 1.5–2 ms + เวลาประมวลผล CRC) | ใช้ **`i2c_lock`** (Mutex ของบัส I²C รอล็อกไม่เกิน 50 ms ตาม A1 ข้อ 7) และเขียนข้อมูลลงตัวแปรกลาง **`air_status`** |
| **2. `Task_Control_Fan`** (คุมพัดลมและไฟสถานะ) | ประเมินสถานะ FSM จากค่า `air_status.co2_ppm`, `room_occupied_count` และ `room_desks_online` เพื่อปรับค่า PWM ของพัดลมดูดอากาศ, เปลี่ยนสีไฟสถานะ RGB LED และอัปเดตฟิลด์สถานะ `fan_pct`, `co2_level`, `temp_flag`, `sensor_ok` ลงใน `air_status` เพื่อให้ A ส่งข้าม Wi-Fi ไปยังโต๊ะทำงาน | **5,000 ms** (5 วินาที) | **1,000 ms** | **~1 ms** (เป็นการเปรียบเทียบค่าตัวแปรและอัปเดตค่า Register ของฮาร์ดแวร์ PWM/GPIO โดยตรง) | อ่าน/เขียนข้อมูลใน **`air_status`**, อ่านค่า **`room_occupied_count`** และ **`room_desks_online`** (รับจากงานสื่อสารของ A) *(หมายเหตุ: ไม่มี output `alert_request` ตามข้อกำหนด A1 v1.0 ข้อ 5)* |

## คำอธิบายเพิ่มเติมสำหรับ B (ใช้เขียนในหัวข้อที่ 5 และ 6)

1. **เหตุผลของการกำหนดคาบเวลา (Period $T_i = 5,000\ \text{ms}$):**
   - คุณภาพอากาศ ($\text{CO}_2$, อุณหภูมิ, ความชื้น) ในห้องปิดมีการเปลี่ยนแปลงทางกายภาพอย่างช้าๆ (Slow physical dynamics) ไม่จำเป็นต้องอ่านค่าระดับมิลลิวินาทีเหมือนเซนเซอร์ตรวจจับคนหรือแสง
   - เซนเซอร์ Sensirion SCD41 ในโหมดมาตรฐาน (Periodic measurement mode) จะทำการวัดและอัปเดตค่าใหม่ทุกๆ **5 วินาที** การตั้งคาบงานย่อยที่ 5,000 ms จึงตรงกับจังหวะฮาร์ดแวร์พอดี ไม่สิ้นเปลืองพลังงาน CPU ไปกับการอ่านค่าซ้ำเดิม
2. **สัดส่วนการใช้งาน CPU (CPU Utilization $U_i = C_i / T_i$):**
   - `Task_Read_Air`: $U_1 = \frac{5\ \text{ms}}{5000\ \text{ms}} = 0.001$ ($0.1\%$)
   - `Task_Control_Fan`: $U_2 = \frac{1\ \text{ms}}{5000\ \text{ms}} = 0.0002$ ($0.02\%$)
   - รวมทั้ง 2 งานย่อยบนโหนดห้องใช้เวลา CPU เพียง **$0.12\%$** เท่านั้น ทำให้ไมโครคอนโทรลเลอร์ ESP32 ของโหนดห้องมีเวลาว่างเหลือเฟือสำหรับการสื่อสารผ่าน Wi-Fi ของ A และสามารถเข้าสู่โหมดประหยัดพลังงาน (Light Sleep / Idle Hook) ในช่วงที่รอครบรอบ 5 วินาทีได้
