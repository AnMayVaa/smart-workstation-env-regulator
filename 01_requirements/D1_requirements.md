## 1. ปัญหาและวัตถุประสงค์ (เล่มหัวข้อ 1.4)

คนทำงานหน้าคอมพิวเตอร์เจอปัจจัยที่ทำให้ล้าหลายอย่างพร้อมกัน ด้านสายตา อาการตาล้าจากการใช้จอดิจิทัลอาจเกิดกับผู้ใช้คอมพิวเตอร์ถึง 50% ขึ้นไป [9] การพักสายตาตามกฎ 20-20-20 ช่วยลดอาการได้ แต่งานวิจัยพบว่าเมื่อเลิกเตือน ผลที่ได้จะหายไปภายใน 1 สัปดาห์ [7] แปลว่าผู้ใช้ต้องมีสิ่งที่เตือนให้อย่างต่อเนื่อง ไม่ใช่ปล่อยให้จำเอง นอกจากนี้การนั่งนานต่อเนื่องก็ทำให้ล้า การลุกเดิน 3 นาทีทุก 30 นาทีช่วยลดความล้าได้ [8]

ด้านอากาศ ห้องทำงานที่ปิดและเปิดแอร์มี CO₂ สะสมจากลมหายใจของคนในห้อง งานวิจัยพบว่าคะแนนการคิดต่ำลง 15% เมื่อ CO₂ อยู่ที่ประมาณ 945 ppm และต่ำลง 50% ที่ประมาณ 1,400 ppm [1] และที่ 1,000 ppm ซึ่งพบได้ทั่วไปในห้องประชุมหรือห้องเรียน ความสามารถในการตัดสินใจลดลง 6 จาก 9 ด้าน [2] ส่วนอุณหภูมิ คนทำงานได้ดีที่สุดที่ประมาณ 22°C และประสิทธิภาพลดลงเมื่ออุณหภูมิสูงขึ้น [5]

ด้านแสง แสงที่ไม่พอหรือไม่คงที่ทำให้ตาต้องปรับตัวตลอดเวลา มาตรฐานแสงสว่างในที่ทำงานกำหนดความสว่างสำหรับงานเขียน อ่าน และใช้คอมพิวเตอร์ไว้ที่ 500 lux [3] สีของแสงก็มีผล แสงขาวอมฟ้าในเวลากลางวันช่วยให้พนักงานตื่นตัวขึ้น ทำงานดีขึ้น และล้าตอนเย็นน้อยลง [4] แต่แสงอมฟ้าในช่วงค่ำกดฮอร์โมนง่วงลงประมาณ 55% ทำให้หลับยากและง่วงกว่าในเช้าวันถัดไป [10]

**วัตถุประสงค์**

โครงงานนี้ออกแบบระบบที่ช่วยลดความล้าและรักษาความตื่นตัวของคนที่ทำงานหน้าคอมพิวเตอร์เป็นเวลานาน โดยดูแลปัจจัย 3 ด้านให้อัตโนมัติและต่อเนื่อง ดังนี้

1) สายตาและร่างกาย: เตือนให้พักสายตาและลุกยืดเส้นตามช่วงเวลาที่งานวิจัยแนะนำ
2) แสง: รักษาความสว่างบนโต๊ะให้ได้ตามมาตรฐาน และปรับสีแสงให้เหมาะกับช่วงเวลาของวัน
3) อากาศ: เฝ้าระวัง CO₂ และระบายอากาศเมื่อเกินเกณฑ์ พร้อมแจ้งเตือนเมื่ออุณหภูมิไม่เหมาะกับการทำงาน

ระบบทำงานเองเป็นหลัก แต่ยังเปิดให้ผู้ใช้ปรับบางอย่างได้ในขอบเขตที่กำหนด เพื่อให้เหมาะกับงานของแต่ละคน

## 2. กลุ่มผู้ใช้ (เล่มหัวข้อ 1.5)

ระบบนี้ออกแบบสำหรับห้องทำงานที่มีคนนั่งทำงานหน้าคอมพิวเตอร์ประจำโต๊ะ กลุ่มผู้ใช้และผู้ได้รับประโยชน์มีดังนี้

| กลุ่ม | ลักษณะ | ได้ประโยชน์อะไร |
|---|---|---|
| พนักงานออฟฟิศ | นั่งทำงานหน้าคอมพิวเตอร์วันละหลายชั่วโมงในห้องแอร์ที่ปิด | ล้าน้อยลงและตื่นตัวขึ้นโดยไม่ต้องจำหรือตั้งค่าเอง |
| นักศึกษาและนักวิจัย | ใช้คอมพิวเตอร์ในห้องเรียน ห้องปฏิบัติการ หรือห้องสมุดเป็นเวลานาน | มีระบบเตือนพักและแสงที่เหมาะกับการอ่านตลอดวัน |
| ผู้ดูแลอาคาร (ไม่ได้ใช้ระบบโดยตรง) | รับผิดชอบค่าไฟและคุณภาพอากาศของห้อง | ไฟและพัดลมปิดเองเมื่อไม่มีคน ช่วยประหยัดพลังงาน |

## 3. Actor และ Use case (ใช้ภายในทีม ยังไม่ลงเล่ม อิงบท 2 หน้า 14–29)

- **Actor:** ผู้ใช้ที่โต๊ะ, ผู้ดูแลระบบ, แสงจากภายนอก, อากาศในห้อง, NTP server, Wi-Fi router
- **Use case หลัก:** ทำงานที่โต๊ะ 1 วัน (มาถึง → นั่ง → ไฟเปิดและปรับ → ได้รับเตือนพัก → ลุก → กลับมา → เลิกงาน → ไฟปิด)
- **Use case อื่น:** ห้องว่างช่วงกลางคืน, ทำงานดึก, ติดตั้งและตั้งค่าครั้งแรก, เซนเซอร์เสีย

| ประเภท scenario (บท 2 หน้า 26) | ตัวอย่าง |
|---|---|
| Main | นั่งทำงานกลางวัน แดดค่อยๆ ลด ไฟเพิ่มความสว่างจนคงที่ 500 lux |
| Extension | ทำงานต่อถึงค่ำ สีแสงค่อยๆ เปลี่ยนเป็นขาวอุ่น / ผู้ใช้เปิดโหมดทำงานดึก |
| Exception | Wi-Fi หลุด, เซนเซอร์อ่านค่าไม่ได้ |
| Variation | คนในห้องเยอะ CO₂ ขึ้นเร็ว พัดลมทำงานนานขึ้น |

## 4. Functional Requirements (เล่มหัวข้อ 2.1)

ความต้องการเชิงหน้าที่ (Functional Requirements: FR) คือสิ่งที่ระบบต้องทำ แต่ละข้อมีรหัสกำกับเพื่อให้แผนทดสอบในหัวข้อ 7 อ้างถึงได้

| รหัส | ข้อความ requirement | โมดูล | ที่มา / เหตุผล |
|---|---|---|---|
| FR-01 | ระบบต้องตรวจว่ามีคนนั่งที่โต๊ะหรือไม่ รวมถึงตอนที่คนนั่งนิ่ง | ตรวจจับคนนั่ง | เป็นฐานของโมดูลแสงและการเตือนพัก |
| FR-02 | ระบบต้องนับเวลาที่ผู้ใช้นั่งต่อเนื่อง และเริ่มนับใหม่เมื่อผู้ใช้ลุกออกนานตามที่กำหนดในการออกแบบโมดูล | ตรวจจับคนนั่ง | ใช้ตัดสินเวลาเตือนพัก |
| FR-03 | ระบบต้องเตือนให้พักสายตาเมื่อผู้ใช้นั่งต่อเนื่องครบ 20 นาที | เตือนพัก | [7] |
| FR-04 | ระบบต้องเตือนให้ลุกยืดเส้นเมื่อผู้ใช้นั่งต่อเนื่องครบ 30 นาที | เตือนพัก | [8] |
| FR-05 | ผู้ใช้ต้องรับทราบการเตือนได้ และเลื่อนการเตือนได้ครั้งละ 5 นาที ติดกันไม่เกิน 2 ครั้ง โดยปิดการเตือนถาวรไม่ได้ | เตือนพัก | [7] เลิกเตือนแล้วผลหายภายใน 1 สัปดาห์, บท 6 หน้า 38 และ 46 |
| FR-06 | ระบบต้องปรับความสว่างบนโต๊ะให้อยู่ที่ 500 lux เมื่อมีคนนั่ง | ความสว่างคงที่ | [3] |
| FR-07 | ผู้ใช้ต้องปรับความสว่างเป้าหมายเพิ่มได้ในช่วง 500–1,000 lux | ความสว่างคงที่ | [3] ค่าปรับเพิ่มสำหรับงานที่ใช้สายตามาก |
| FR-08 | ระบบต้องหรี่ไฟเหลือ 50% เมื่อไม่มีคนนั่งครบ 5 นาที แล้วค่อยๆ ปิด และต้องเปิดไฟเมื่อตรวจพบคนกลับมา | ความสว่างคงที่ | [12] |
| FR-09 | ระบบต้องปรับสัดส่วนแสงขาวเย็นกับขาวอุ่นตามช่วงเวลาของวัน และใช้สัดส่วนกลางเมื่อยังไม่รู้เวลา | สีแสงตามเวลา | [4], [10] |
| FR-10 | ผู้ใช้ต้องเปิดโหมดทำงานดึกได้ เพื่อใช้แสงสีเดียวกับเวลากลางวันต่อหลัง 19:00 | สีแสงตามเวลา | ผู้ใช้เลือกเองระหว่างความตื่นตัวกับการนอน [10], บท 6 หน้า 38 |
| FR-11 | ค่าที่ผู้ใช้ปรับเอง (ความสว่างเป้าหมายและโหมดทำงานดึก) ต้องกลับเป็นค่าเริ่มต้นเมื่อไม่มีคนนั่งครบ 5 นาที | ความสว่างคงที่ / สีแสง | ผู้ใช้คนถัดไปเริ่มจากค่ามาตรฐานเสมอ |
| FR-12 | ระบบต้องวัด CO₂ อุณหภูมิ และความชื้นในห้องทุก 5 วินาที | อากาศ / อุณหภูมิ / ความชื้น | รอบการวัดของเซนเซอร์ [13] |
| FR-13 | ระบบต้องเปิดพัดลมดูดอากาศเมื่อ CO₂ ถึง 1,000 ppm และปิดเมื่อ CO₂ ลดลงถึง 800 ppm | อากาศ | [1], [2], [13] |
| FR-14 | ระบบต้องแสดงระดับคุณภาพอากาศที่ไฟสถานะของห้องและบนจอของทุกโต๊ะ | อากาศ | ให้ผู้ใช้รู้สาเหตุเมื่อรู้สึกง่วง |
| FR-15 | ระบบต้องลดความแรงหรือปิดพัดลมเมื่อไม่มีคนนั่งโต๊ะใดในห้องเลย | อากาศ | ประหยัดพลังงาน |
| FR-16 | ค่าเกณฑ์ของระบบและการทำงานของพัดลมต้องเปลี่ยนได้โดยผู้ดูแลระบบเท่านั้น ผู้ใช้ที่โต๊ะเปลี่ยนไม่ได้ | อากาศ / ทั้งระบบ | พัดลมและอากาศเป็นของที่ทุกคนในห้องใช้ร่วมกัน |
| FR-17 | ระบบต้องเตือนเมื่ออุณหภูมิห้องต่ำกว่า 20°C หรือสูงกว่า 26°C โดยไม่สั่งงานเครื่องปรับอากาศ | อุณหภูมิ | [5] |
| FR-18 | ระบบต้องแสดงค่าความชื้นบนจอ โดยไม่มีการเตือน | ความชื้น | [6] |
| FR-19 | โหนดโต๊ะต้องส่งสถานะการนั่งให้โหนดห้อง และโหนดห้องต้องส่งข้อมูลอากาศให้โหนดโต๊ะ | การสื่อสาร | ตารางข้อมูลกลาง |
| FR-20 | ระบบต้องรับเวลาจริงจาก NTP server และนับเวลาต่อเองเมื่อเชื่อมต่อไม่ได้ | การสื่อสาร | ใช้กับ FR-09 |

## 5. Non-Functional Requirements (เล่มหัวข้อ 2.2)

ความต้องการที่ไม่ใช่เชิงหน้าที่ (Non-Functional Requirements: NFR) คือระบบต้องทำได้ดีแค่ไหน ทุกข้อเขียนให้วัดหรือตรวจได้

| รหัส | ข้อความ requirement | โมดูล | ที่มา / เหตุผล |
|---|---|---|---|
| **เวลาตอบสนอง** | | | |
| NFR-01 | ระบบต้องเปิดพัดลมภายใน 10 วินาทีหลัง CO₂ เกิน 1,000 ppm | อากาศ | รอบอ่านค่า 5 วินาที × 2 |
| NFR-02 | หลังแสงภายนอกเปลี่ยน ระบบต้องกลับมาที่ความสว่างเป้าหมาย ± 50 lux ภายใน 10 วินาที | ความสว่างคงที่ | ปรับไม่เกิน 2% ต่อรอบ 200 ms |
| NFR-03 | ไฟต้องเริ่มสว่างขึ้นภายใน 1 วินาทีหลังตรวจพบคนกลับมานั่ง | ความสว่างคงที่ | รอบตรวจคน 100 ms + รอบคุมแสง 200 ms |
| NFR-04 | ระบบต้องแสดงการเตือนพักภายใน 1 วินาทีหลังครบเวลา | เตือนพัก | รอบนับเวลา 1 วินาที |
| NFR-05 | งานย่อยทุกงานในโหนดต้องทำเสร็จก่อนเส้นตายของตัวเอง | ทุกโหนด | บท 17 หน้า 19–21 |
| **ความทนทานเมื่อเกิดความผิดพลาด** | | | |
| NFR-06 | ถ้า Wi-Fi หลุด โหนดโต๊ะต้องยังคุมแสง ตรวจคน และเตือนพักได้ครบ และโหนดห้องต้องยังคุมพัดลมได้ | ทุกโหนด | ประมวลผลในตัวโหนด บท 24 หน้า 17 |
| NFR-07 | ถ้าเซนเซอร์ตัวใดอ่านค่าไม่ได้ 3 รอบติดกัน ระบบต้องเข้าสถานะปลอดภัยของโมดูลนั้นและแจ้งเตือนบนจอ | ทุกโมดูล | บท 2 หน้า 27, บท 6 หน้า 37 |
| **พลังงาน** | | | |
| NFR-08 | เมื่อไม่มีคนนั่งครบ 5 นาที ไฟโต๊ะต้องปิด และโหนดโต๊ะต้องลดงานที่ไม่จำเป็นลง | ตรวจคน / แสง | บท 10 หน้า 36 |
| **คุณภาพแสง** | | | |
| NFR-09 | PWM ของไฟ LED ต้องมีความถี่ไม่ต่ำกว่า 3 kHz (ระบบใช้ 5 kHz) | ความสว่างคงที่ | บท 13 หน้า 93–95, [11] |
| NFR-10 | การเปลี่ยนสีแสงอัตโนมัติตามเวลาต้องเปลี่ยนสัดส่วนสีไม่เกิน 1% ต่อนาที | สีแสงตามเวลา | ให้ผู้ใช้ไม่รู้สึกว่าแสงเปลี่ยนกะทันหัน |
| NFR-11 | การเปิดไฟ ปิดไฟ และการเปลี่ยนตามคำสั่งของผู้ใช้ ต้องค่อยๆ เปลี่ยนในเวลาไม่น้อยกว่า 2 วินาที | ความสว่างคงที่ / สีแสง | ไม่ให้แสงกระชาก |
| NFR-12 | ระบบต้องวัดแสงได้ในช่วง 0–2,000 lux และวัด CO₂ ได้ในช่วง 400–5,000 ppm | แสง / อากาศ | บท 13 หน้า 18 |
| **การขยายระบบ** | | | |
