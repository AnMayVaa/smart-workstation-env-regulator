## 5.1.x แผนภาพสถานะของโมดูลแสง

โมดูลแสงทำงานเป็นงานย่อย `light_control_task` ทุก 200 ms และแบ่ง logic เป็น 2 ส่วนที่ทำงานพร้อมกัน ตามแนวคิด AND super-state (บท 3 หน้า 49–78) ส่วนแรกตัดสินว่าไฟควรเปิด หรี่ หรือปิด และคุมความสว่างรวม (B) ส่วนที่สองตัดสินสัดส่วนแสงขาวเย็น (r) ตามช่วงเวลาของวัน จากนั้นนำสองค่ามารวมกันเป็นค่า duty ของ PWM ทั้งสองช่อง คือ ช่องขาวเย็นเท่ากับ B × r และช่องขาวอุ่นเท่ากับ B × (1 − r) การแยกแบบนี้ทำให้การเปลี่ยนสีไม่กระทบความสว่าง เพราะวงควบคุมจะปรับ B ให้แสงบนโต๊ะกลับมาที่ค่าเป้าหมายเองเสมอ

**ภาพที่ 5.x** แผนภาพสถานะของโมดูลแสง (ซ้าย: สถานะไฟ / ขวา: สีแสง)

**ตารางที่ 5.x สถานะไฟ**

| สถานะ | ความหมาย | การทำงาน |
|---|---|---|
| S0 OFF | ไม่มีคน | ปิดไฟ |
| S1 REGULATING | มีคนนั่ง เซนเซอร์ปกติ | อ่านแสงทุก 200 ms ถ้าต่างจากเป้าหมายเกิน ±25 lux ให้ปรับ B ทีละไม่เกิน 2% |
| S2 DIMMING | ไม่มีคนครบ 5 นาที | หรี่เหลือ 50% ค้าง 60 วินาที แล้วค่อยๆ ปิด ถ้าคนกลับมาก่อน ไฟกลับไปสว่างเท่าเดิม |
| S3 SENSOR_FAULT | อ่านเซนเซอร์แสงไม่ได้ 3 รอบติดกัน | ค้างไฟที่ 60% และแจ้งเตือนบนจอ จนกว่าจะอ่านได้ปกติ 2 รอบติดกัน |

**ตารางที่ 5.x สถานะสีแสง**

| สถานะ | เวลา / เงื่อนไข | สัดส่วนแสงขาวเย็น (r) |
|---|---|---|
| C0 NEUTRAL | ยังไม่ได้เวลาจากเครือข่าย | 0.50 |
| C1 DAY | 07:00–16:59 | 0.80 |
| C2 TRANSITION | 17:00–18:59 | ลดลงจาก 0.80 เป็น 0.00 ภายใน 120 นาที |
| C3 EVENING | 19:00–06:59 | 0.00 |
| C4 LATE_MODE | ผู้ใช้เปิดโหมดทำงานดึก | 0.80 |

ทุกการเปลี่ยนแปลงของแสงเป็นแบบค่อยเป็นค่อยไป การเปลี่ยนสีอัตโนมัติไม่เกิน 1% ต่อนาที การเปิดไฟใช้เวลา 2 วินาที การปิดไฟใช้เวลา 5 วินาที และการเปลี่ยนตามคำสั่งผู้ใช้ใช้เวลา 10 วินาที โดยใช้ฟังก์ชัน fade ของวงจร PWM ในตัว ESP32 ซึ่งไล่ค่า duty เองโดยไม่ใช้เวลาประมวลผลของ CPU

## 5.2.x Pseudocode ของโมดูลแสง

```text
TASK light_control_task (period = 200 ms):
  LOOP FOREVER:
    snap = read_snapshot(occupied, away_timeout, time_of_day, time_valid,
                         user_lux_target, late_mode)
    IF take(i2c_lock, 50 ms) THEN ok = bh1750_read_lux(&lux); give(i2c_lock)
    ELSE ok = FALSE
    update_error_counters(ok)
    target = clamp(snap.user_lux_target, 500, 1000)   // ไม่มีค่า = 500

    SWITCH light_state:
      S0_OFF:        IF snap.occupied → fade_on(2 s) → S1_REGULATING
      S1_REGULATING: IF snap.away_timeout → enter_dimming()
                     ELSE IF err_count >= 3 → B = 60%, alert(SHOW) → S3_SENSOR_FAULT
                     ELSE IF ok AND |target - lux| > 25:
                          B += clamp(0.02 × (target - lux), -2, +2)
      S2_DIMMING:    IF snap.occupied → restore B (2 s) → S1_REGULATING
                     ELSE IF held 60 s → fade_off(5 s) → S0_OFF
      S3_SENSOR_FAULT: IF snap.away_timeout → enter_dimming()
                     ELSE IF ok_count >= 2 → alert(CLEAR) → S1_REGULATING

    r_target = late_mode ? 0.80 : (time_valid ? schedule(time) : 0.50)
    r = move_toward(r, r_target, late_mode_changed ? 10 s : 1% per minute)

    ledc_fade(CH_CW, B × r) ; ledc_fade(CH_WW, B × (1 - r))
    wait_until_next_period()
```

เมื่อเข้าสถานะ S2 ระบบจะล้างค่าที่ผู้ใช้ปรับเองทั้งหมด (ความสว่างเป้าหมายและโหมดทำงานดึก) เพื่อให้ผู้ใช้คนถัดไปเริ่มจากค่ามาตรฐานเสมอ ส่วนค่าที่ผู้ใช้ป้อนนอกช่วง 500–1,000 lux จะถูกปัดเข้าช่วง ตามหลักการออกแบบให้รองรับความผิดพลาดของผู้ใช้ (บท 6 หน้า 46)
