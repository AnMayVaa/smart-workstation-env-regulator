# บทบาท C: โมดูลอากาศ + ภาพจำลอง + แผนทดสอบ

> อ่านคู่กับ `00_overview.md` (ภาพรวมโปรเจค)
> ถ้ามีเวลาน้อย อ่านแค่ **"สรุป 30 วินาที"** กับ **"ของที่ต้องส่ง"** ก็พอเริ่มงานได้

---

## สรุป 30 วินาที

- คุณดูแล **อากาศในห้อง** (CO₂ อุณหภูมิ ความชื้น และพัดลมดูดอากาศ) และ **งานนำเสนอ** (ภาพจำลอง + แผนทดสอบ)
- **ฮาร์ดแวร์:** เลือกเซนเซอร์อากาศ พัดลมดูดอากาศกับวงจรขับ และไฟสถานะ 3 สี
- **ซอฟต์แวร์:** คิด logic อ่านค่าอากาศ เปิดปิดพัดลม และสิ่งที่ระบบทำเมื่อเซนเซอร์เสีย **ไม่ต้องเขียนโค้ดจริง** A เป็นคนเขียน
- **งานหลัก:** (1) ภาพจำลองตัวอุปกรณ์ และภาพการติดตั้งในห้อง (2) รวม test case ของทุกคนเป็นแผนทดสอบ
- **งานแรกที่ต้องทำ (M2):** ส่งอุปกรณ์ (C1) และ logic (C2) A รออยู่ ระหว่างนั้นเริ่มภาพติดตั้งในห้อง (C3) ได้เลย เพราะไม่ต้องรอใคร

## หน้าที่ของคุณ

| ด้าน | ทำอะไร |
|---|---|
| ฮาร์ดแวร์ | เลือกเซนเซอร์ CO₂/อุณหภูมิ/ความชื้น, พัดลมดูดอากาศ + วงจรขับ, ไฟสถานะ RGB พร้อมเหตุผลและ datasheet |
| ซอฟต์แวร์ | logic อ่านค่าอากาศ, ตัดสินใจเปิดปิดหรือปรับความแรงพัดลม, แบ่งระดับเตือน (ดี / เริ่มแย่ / แย่), ทำอะไรเมื่อเซนเซอร์เสีย, ลดพัดลมเมื่อห้องว่าง |
| งานหลัก | ภาพจำลองอุปกรณ์ + ภาพติดตั้งในห้อง (มองเฉียงแบบ isometric) พร้อมเหตุผลตำแหน่งติดตั้ง · รวม test case ของทุกคนเป็นแผนทดสอบ |
| เอกสาร | หัวข้อ 3 (ภาพติดตั้ง), 4 และ 5 (ส่วนโมดูลตัวเอง), 7 (แผนทดสอบ) และภาพประกอบหัวข้อ 1 |

## ของที่ต้องส่ง (เรียงตาม Milestone)

วันที่ของแต่ละ M ดูได้จากกลุ่มแชท D เป็นคนกำหนด
**ความสำคัญ:** 🔴 มีคนรอ · 🟡 มีคนใช้ทีหลัง · 🟢 ใช้ตอนรวมเล่ม

### [M2] C1 อุปกรณ์ของโมดูล 🔴

- **คืออะไร:** รายการอุปกรณ์ที่คุณเลือก พร้อมเหตุผล
- **อุปกรณ์ที่แนะนำ:**
  - SCD41: วัด CO₂ ได้จริงแบบ NDIR และวัดอุณหภูมิกับความชื้นได้ในตัวเดียว ห้ามใช้ MQ-135 เพราะวัด CO₂ จริงไม่ได้
  - พัดลมดูดอากาศ DC 12V + MOSFET + flyback diode
  - ไฟ RGB แสดงสถานะ
- **ต้องรู้ไว้:** พัดลมตั้งโต๊ะลด CO₂ ไม่ได้ เพราะแค่พัดอากาศเดิมวนในห้อง ต้องเป็นพัดลมที่ดูดอากาศออกนอกห้อง
- **ต้องมี:** กรอกตาม **แบบฟอร์ม HW** และแนบ datasheet ทุกตัว
- **ส่งให้:** A (ใช้ทำผังขาและคำนวณไฟ), D
- **ส่งที่:** `03_hardware/C1_hardware_air_v1` และ datasheet ไว้ใน `03_hardware/datasheets/`
- **ไปลงเอกสาร:** หัวข้อ 4 (Sensor/Actuator choice and justification)
- **✅ เช็คก่อนส่ง**
  - [ ] อุปกรณ์ทุกตัวมีเหตุผล และบอกว่าเทียบกับตัวเลือกอื่นอะไร
  - [ ] ระบุไฟเลี้ยง (V, mA) และวิธีต่อ (I²C / PWM / GPIO) ครบทุกตัว
  - [ ] แนบ datasheet ครบทุกตัว
  - [ ] ระบุว่าในโปรแกรมจำลองใช้อะไรแทน (potentiometer แทน CO₂, DHT22 แทนอุณหภูมิและความชื้น, LED แทนพัดลม)

### [M2] C2 Logic ของโมดูล 🔴

- **คืออะไร:** แผนภาพสถานะ (FSM) + pseudocode ของการดูแลอากาศ
- **ต้องคิดเรื่องเหล่านี้:**
  - **Hysteresis:** เปิดพัดลมที่ 1000 ppm แต่ปิดที่ค่าต่ำกว่า เช่น 800 ppm เพื่อไม่ให้พัดลมเปิดปิดถี่ อธิบายเหตุผลด้วย
  - **ระดับเตือน:** แบ่งเป็น 3 ระดับ (ดี / เริ่มแย่ / แย่) แต่ละระดับไฟสถานะเป็นสีอะไร
  - **อุณหภูมิ:** เตือนอย่างเดียว ไม่คุมแอร์ ค่าที่ดีที่สุด 21–22°C (อ้างอิง [5])
  - **เซนเซอร์เสียหรืออ่านค่าไม่ได้:** แนะนำให้เปิดพัดลมไว้ก่อนเพื่อความปลอดภัย และแจ้งเตือน (รูปแบบ ตรวจจับ → ตอบสนอง → แจ้งเตือน บท 6 หน้า 22–26)
  - **ห้องว่าง:** ถ้า `room_occupied_count` = 0 ลดหรือปิดพัดลมเพื่อประหยัดไฟ
- **ต้องมี:** กรอกตาม **แบบฟอร์ม LOGIC**
- **ส่งให้:** A (ใช้เขียนโค้ดจริง)
- **ส่งที่:** `04_logic/C2_logic_air_v1` และภาพ FSM ไว้ใน `07_visuals/`
- **ไปลงเอกสาร:** หัวข้อ 5 (Flowcharts/UML, Pseudocode)
- **✅ เช็คก่อนส่ง**
  - [ ] ทุกสถานะมีทางเข้าและทางออก
  - [ ] ค่าเกณฑ์ตรงกับ D1 และมีที่มา
  - [ ] ข้อมูลรับเข้าและส่งออกตรงกับตารางข้อมูลกลาง (A1)
  - [ ] มีกรณีเซนเซอร์เสีย

### [M3] C3 ภาพการติดตั้งในห้อง 🟡 (เริ่มได้ตั้งแต่ M1)

- **คืออะไร:** ภาพห้องทำงานมองเฉียงจากมุมบน (isometric) แสดงตำแหน่งโหนดโต๊ะ โหนดห้อง และพัดลมดูดอากาศ
- **ต้องมี:** ภาพ + คำอธิบายเหตุผลของตำแหน่งติดตั้ง เช่น
  - เซนเซอร์แสงวัดที่ระดับผิวโต๊ะ
  - เซนเซอร์ CO₂ อยู่ระดับที่คนนั่งหายใจ และห่างจากประตูหน้าต่าง
  - พัดลมดูดอากาศอยู่ผนังติดภายนอก
- **เครื่องมือ:** Tinkercad 3D หรือ SketchUp (ฟรี) หรือวาดเองแล้ว export เป็น PNG
- **ส่งให้:** D | **ส่งที่:** `07_visuals/C3_room_installation_v1`
- **ไปลงเอกสาร:** หัวข้อ 3 (มุมมองการติดตั้ง), เหตุผลตำแหน่งลงหัวข้อ 4
- **✅ เช็คก่อนส่ง**
  - [ ] มีครบทั้งโหนดโต๊ะ โหนดห้อง พัดลม และ router
  - [ ] ทุกตำแหน่งมีเหตุผล
  - [ ] ภาพชัดพอเมื่อย่อลงในหน้ากระดาษ

### [M3] C4 ภาพจำลองตัวอุปกรณ์ 🟡

### แบบฟอร์ม HW: อุปกรณ์

1. **สถานะทั้งหมด:** ชื่อและความหมาย

| จากสถานะ | ไปสถานะ | เงื่อนไข | สิ่งที่ระบบทำ |

## แนวทางการทำงานของบทบาทนี้

- เน้นงานเอกสาร ภาพ และการนำเสนอ อธิบายเรื่องเทคนิคแบบเข้าใจง่าย และยกตัวอย่างประกอบ
- บทบาทนี้ **ไม่ต้องเขียนโค้ดจริง** ส่ง FSM, pseudocode, ภาพ และแผนทดสอบ
- ห้ามเปลี่ยนค่าเกณฑ์ (ของ D) และตารางข้อมูลกลาง (ของ A) เอง
- ข้อมูลเรื่องตำแหน่งติดตั้งเซนเซอร์และ datasheet เป็นข้อมูลนอกสไลด์ ต้องบอกแหล่งเสมอ
- ก่อนแจ้งว่างานพร้อมส่ง ตรวจ "เช็คก่อนส่ง" ทุกข้อ
