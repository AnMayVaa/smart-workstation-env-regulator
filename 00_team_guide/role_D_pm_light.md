# บทบาท D: PM + โมดูลแสง + รวมเล่ม

> อ่านคู่กับ `00_overview.md` (ภาพรวมโปรเจค) คุณเป็นผู้ดูแลไฟล์ภาพรวม
> ถ้ามีเวลาน้อย อ่านแค่ **"สรุป 30 วินาที"** กับ **"ของที่ต้องส่ง"** ก็พอเริ่มงานได้

---

## สรุป 30 วินาที

- คุณเป็น **PM และบรรณาธิการ** ของโปรเจค
- **ฮาร์ดแวร์:** เลือกเซนเซอร์แสงและไฟ LED 2 สีกับวงจรขับ
- **ซอฟต์แวร์:** คิด logic คุมความสว่างให้คงที่ และเปลี่ยนสีแสงตามช่วงเวลา **ไม่ต้องเขียนโค้ดจริง** A เป็นคนเขียน
- **งานหลัก:** เขียน requirement, กำหนดวันของแต่ละ milestone, ตามงาน, รวมเล่ม และเขียนบทคัดย่อ
- **งานแรกที่ต้องทำ (M1):** ส่ง requirement + ค่าเกณฑ์ (D1) ทุกคนรออยู่ และกำหนดวันที่ของ M1–M6

## ของที่ต้องส่ง (เรียงตาม Milestone)

**ความสำคัญ:** 🔴 มีคนรอ · 🟡 มีคนใช้ทีหลัง · 🟢 ใช้ตอนรวมเล่ม

### [M1] D0 กำหนดวันที่และเปิดโฟลเดอร์กลาง 🔴

- ใส่วันที่ของ M1–M6 ในไฟล์ภาพรวมข้อ 8 แล้วแจ้งในกลุ่ม
- สร้างโฟลเดอร์กลางตามโครงในไฟล์ภาพรวมข้อ 11 แล้วใส่ลิงก์
- ให้ทุกคนเลือกบทบาท A/B/C แล้วบันทึกชื่อจริงไว้ (ใช้ในตาราง role ของเอกสาร)

### [M1] D1 Requirement + ค่าเกณฑ์ 🔴

- **คืออะไร:** รายการว่าระบบต้องทำอะไร (FR) และต้องทำได้ดีแค่ไหน (NFR) พร้อมค่าเกณฑ์ทุกตัวและที่มา
- **FR กับ NFR ต่างกันยังไง**
  - **FR = ระบบ "ทำอะไร"** เขียนเป็น "ระบบต้อง + กริยา" เช่น "ระบบต้องเตือนเมื่อ CO₂ เกินเกณฑ์"
  - **NFR = ระบบทำ "ได้ดีแค่ไหน"** มักมีตัวเลข เช่น "ต้องเตือนภายใน 10 วินาทีหลังค่าเกิน 1000 ppm", "ถ้า Wi-Fi หลุด โหนดโต๊ะยังทำงานได้ครบ"
- **ต้องมี:**
  - FR ของทุกโมดูล ใส่รหัส (FR-01, FR-02 …) เพื่อให้ test case อ้างถึงได้
  - NFR ด้านเวลาตอบสนอง, พลังงาน, ความทนทานเมื่อเกิดความผิดพลาด, การขยายระบบ ใส่รหัส (NFR-01 …)
  - ตารางค่าเกณฑ์ (เริ่มจากไฟล์ภาพรวมข้อ 4) ยืนยันค่าที่ยังเป็นร่าง เช่น CO₂ ปิดพัดลม 800 ppm และไม่มีคน 5 นาที
  - กลุ่มผู้ใช้ และ use case หลัก (บท 2 หน้า 14–41)
- **ส่งให้:** ทุกคน
- **ส่งที่:** `01_requirements/D1_requirements_v1`
- **ไปลงเอกสาร:** หัวข้อ 1 (Objective, Target users), 2 (Functional / Non-functional requirements)
- **✅ เช็คก่อนส่ง**
  - [ ] ทุกโมดูลในไฟล์ภาพรวมข้อ 2 มี FR อย่างน้อย 1 ข้อ
  - [ ] NFR ทุกข้อวัดได้ (มีตัวเลขหรือเงื่อนไขที่ตรวจได้)
  - [ ] ค่าเกณฑ์ทุกตัวมีที่มา
  - [ ] A ดูแล้วว่าตรงกับตารางข้อมูลกลาง

### [M2] D2 อุปกรณ์ของโมดูลแสง 🔴

- **อุปกรณ์ที่แนะนำ:**
  - BH1750: อ่านค่าเป็น lux ได้ตรงๆ ต่อทาง I²C
  - LED ขาวเย็น + ขาวอุ่น 12V
  - MOSFET แบบที่เปิดได้เต็มที่ด้วยไฟ 3.3V เพราะขา GPIO จ่ายกระแสไม่พอ (บท 13 หน้า 34–35)
- **ต้องมี:** กรอกตาม **แบบฟอร์ม HW** และแนบ datasheet ทุกตัว
- **ส่งให้:** A | **ส่งที่:** `03_hardware/D2_hardware_light_v1`
- **ไปลงเอกสาร:** หัวข้อ 4
- **✅ เช็คก่อนส่ง**
  - [ ] อุปกรณ์ทุกตัวมีเหตุผลและตัวเลือกที่เทียบ
  - [ ] ระบุไฟเลี้ยงและวิธีต่อครบ
  - [ ] แนบ datasheet ครบ
  - [ ] ระบุว่าในโปรแกรมจำลองใช้อะไรแทน (photoresistor แทน BH1750, LED แทนแถบไฟ)

### [M2] D3 Logic ของโมดูลแสง 🔴

- **ต้องคิดเรื่องเหล่านี้:**
  - วงควบคุมแบบป้อนกลับ: อ่าน `lux_now` → เทียบกับ 500 lux → ปรับ PWM ทีละนิด → อ่านซ้ำ
  - คาบ PWM ของ LED 1–5 ms เพื่อไม่ให้ไฟกะพริบ (บท 13 หน้า 95)
  - สีแสงตาม `time_of_day`: กลางวันใช้ขาวเย็นมากกว่า ตอนเย็นใช้ขาวอุ่นมากกว่า (อ้างอิง [4])
  - `occupied` = เท็จ นานตามเกณฑ์ → ค่อยๆ หรี่แล้วปิด
  - ถ้าไม่ได้เวลาจาก NTP (Wi-Fi หลุด) จะใช้สีไหน
- **ต้องมี:** กรอกตาม **แบบฟอร์ม LOGIC**
- **ส่งให้:** A | **ส่งที่:** `04_logic/D3_logic_light_v1` และภาพ FSM ไว้ใน `07_visuals/`
- **ไปลงเอกสาร:** หัวข้อ 5

### [M2] D-T และ D-TC 🔴 / 🟡

- **D-T:** งานย่อยคุมแสง (ทุก 200 ms) ตาม **แบบฟอร์ม T** ส่งให้ B → `05_tasks/D-T_tasks_v1`
- **D-TC:** test case 2–3 ข้อ เช่น "แสงภายนอกลดลง ระบบเพิ่มไฟจนกลับมาที่ 500 ± 50 lux" ส่งให้ C → `06_testing/D-TC_testcases_v1`

### [M5] D4 เนื้อหาเอกสารของคุณ 🟢 (เริ่มเขียนได้ตั้งแต่ M2)

- **หัวข้อ 1:** ชื่อ, สมาชิกและบทบาท, ปัญหาที่จะแก้พร้อมตัวเลขวิจัย, กลุ่มผู้ใช้
- **หัวข้อ 2:** FR / NFR (จาก D1)
- **หัวข้อ 3:** ภาพรวมระบบและหน้าที่ของแต่ละโมดูล
- **หัวข้อ 4 และ 5:** ส่วนโมดูลแสง
- **หัวข้อ 6:** ขั้นตอนการออกแบบ (เช่น Extended Waterfall บท 1 หน้า 39–48) และ trade-off ที่สำคัญ เช่น เลือก Wi-Fi แทน Zigbee, mmWave แทน PIR, ใช้ RTOS แทนการวนลูปธรรมดา
- **หัวข้อ 8:** รวมจาก X-N ของทุกคน
- **หัวข้อ 9:** ขยายเป็นหลายห้องหรือต่อ cloud (บท 24), เพิ่มฟีเจอร์, ประหยัดพลังงาน, ความปลอดภัยของข้อมูล (บท 26)

### [M6] D5 เล่มสมบูรณ์ 🔴

- รวมงานทุกคนเป็นเล่มเดียว เรียงตาม 10 หัวข้อของ Instruction
- เขียนบทคัดย่อ 150–200 คำ เป็นอย่างสุดท้าย
- จัดอ้างอิงเป็น IEEE ทั้งเล่ม
- ใส่ตารางบทบาทของสมาชิก (Instruction บังคับ)
- **✅ เช็คก่อนส่งอาจารย์**
  - [ ] ครบทุกหัวข้อย่อยตาม Instruction (เทียบกับไฟล์ Instruction PDF ทีละข้อ และตาราง "ใครเขียนหัวข้อไหน" ในไฟล์ภาพรวมข้อ 7)
  - [ ] ตัวเลขทั้งเล่มตรงกัน (ค่าเกณฑ์ในหัวข้อ 2, 5, 7 เป็นค่าเดียวกัน)
  - [ ] ชื่อเรียกโมดูลและข้อมูลเหมือนกันทั้งเล่ม
  - [ ] ภาพทุกภาพมีหมายเลขและคำบรรยาย
  - [ ] ทุกคนในทีมอ่านและรับรองส่วนของตัวเองแล้ว

## งาน PM ระหว่างทาง

- **หลังวันกำหนดของแต่ละ M:** ไล่เช็คตาราง "รายการของที่ต้องส่ง" ในไฟล์ภาพรวมข้อ 9 ว่าใครยังไม่ส่ง แล้วทวง
- **เฝ้าเส้นทางวิกฤต:** D1 + A1 → logic ของ B/C/D → A เขียนโค้ดและจำลอง → ผลทดสอบ → รวมเล่ม ถ้าใครช้าในเส้นนี้ ให้จัดการก่อนเรื่องอื่น
- **เมื่อมีคนขอเปลี่ยนของกลาง** (โมดูล, ค่าเกณฑ์, ตารางข้อมูลกลาง): ตัดสินร่วมกับ A แล้วอัปเดตไฟล์ภาพรวม และแจ้งทุกคน
- **ถ้ามีคนหายหรือส่งไม่ได้:** แบ่งงาน 🔴 ของคนนั้นให้คนอื่นก่อน เพราะมีคนรออยู่

## สำหรับ AI ที่ช่วยบทบาทนี้

- ผู้ใช้เป็น PM และผู้ดูแลไฟล์ภาพรวม ช่วยเรื่อง requirement, การตามงาน, การตรวจความสอดคล้องของเอกสาร และการเรียบเรียงภาษา
- ภาษาในเอกสาร: ไทยแบบรายงาน อธิบายให้คนอ่านเข้าใจ ไม่ทางการจนอ่านยาก
- อ้างอิงสไลด์ของวิชาก่อนเสมอ ข้อมูลนอกสไลด์ต้องอ้างแบบ IEEE
- ตอนรวมเล่ม ให้ตรวจว่าตัวเลข ชื่อโมดูล และชื่อข้อมูลตรงกันทั้งเล่ม และทุกหัวข้อย่อยตาม Instruction มีครบ
- ก่อนบอกว่างานพร้อมส่ง ให้ตรวจ "เช็คก่อนส่ง" ทุกข้อ
